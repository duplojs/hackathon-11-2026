# Exercice 10 : asynchronisme

> **État :** ✅ sortie Go identique à TypeScript **[observé, `./scripts/check.sh 10` sur `main` `f0a10cf`]**.

## Problème étudié

Source : [`projects/10`](../../projects/10). Trois calculs peuvent échouer ;
`rightAsyncPipe` compose leurs étapes, `asyncGroup` regroupe les résultats et
`DCommon.asyncPipe` applique la conversion des valeurs. Le point essentiel est
l'ordre séquentiel des appels et l'arrêt au premier `Left`.

Sortie TypeScript observée :

```text
[ 'transaction annulée' ]
```

## Stratégie

L'option A d'[ADR-5](../decisions/ADR-5-async.md) traduit les pipelines comme des
appels Go synchrones séquentiels. `rightAsyncPipe` réutilise le handler de
`rightPipe`; `asyncGroup` appelle chaque fabrique dans la boucle, avant de
continuer uniquement si le résultat est Right ; `DCommon.asyncPipe` réutilise
le handler de `pipe`. Les fabriques ne sont pas appelées en avance, ce qui
préserve l'arrêt au premier `Left`.

La forme tableau d'`asyncGroup` est prise en charge. La forme objet est refusée
explicitement. Aucun goroutine ni channel n'est produit.

## Go produit

**[observé]** Extrait de `projects/10/dist/index.ts/index.ts.go` (`main` `f0a10cf`). `asyncGroup` devient une boucle qui appelle chaque fabrique, s'arrête au premier `Left` et n'utilise ni goroutine ni channel :

```go
Generated_29 := ([]func() (shard_dependencies.Either[float64]){
	Generated_18,
	Generated_23,
	Generated_28,
})
Generated_30 := make([]float64, 0, len(Generated_29))
Generated_34 := false
var Generated_31 shard_dependencies.Either2[float64, []float64]
for _, Generated_32 := range Generated_29 {
	Generated_33 := Generated_32()
	if Generated_33.IsLeft() {
		Generated_31 = shard_dependencies.Either2FromLeft[float64, []float64](Generated_33)
		Generated_34 = true
		break
	}
	Generated_30 = append(Generated_30, Generated_33.Value)
}
if !(Generated_34) {
	Generated_31 = shard_dependencies.Either2SuccessOf[float64, []float64](Generated_30)
}
```

`calculate` (une fonction `async`) devient une fonction Go synchrone dont le `rightAsyncPipe` est traduit en `if` imbriqués, comme le `rightPipe` de l'exercice 07. Le résultat de `asyncGroup` a des côtés différents (`Left<…, number> | Success<number[]>`), d'où `Either2` (ADR-12).

**[observé]** `go build -gcflags=-m ./...` dans `projects/10/dist` : les trois fabriques sont signalées `func literal does not escape` (lignes 46, 53 et 60) ; le code utilisateur compte 10 lignes « escapes to heap », toutes des slices, comme le relève [`docs/measures.md`](../measures.md) (même nombre, Apple M4). De bout en bout : Go 2,0 ms contre 17,6 ms pour Node sur le JS compilé (même source).

## Variantes

Voir [`variations/README.md`](../../variations/README.md) :
`10-group-lazy-stop`, `10-right-async-pipe-left`, `10-async-pipe-plain`,
`10-await-direct` et `10-sync-between`.

**[observé, `./scripts/check-all.sh --variations` sur `main` `f0a10cf`]** Quatre variantes sont identiques à TypeScript. `10-sync-between` échoue **au diff seulement**, c'est la limite assumée de l'ADR-5 : JavaScript affiche l'effet synchrone avant les fabriques, l'option A les exécute dans l'appel Go inliné. La valeur finale est la même :

```diff
-synchronous effect before await
 factory 1
 factory 2
+synchronous effect before await
```

## Limites et validation restante

- L'option A ne reproduit pas l'intercalage des microtâches avec du code
  synchrone et n'est pas un modèle général des E/S asynchrones.
- L'objet `asyncGroup` est hors périmètre et refusé explicitement.
