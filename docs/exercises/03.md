# Exercice 03 : composer des transformations dans un `pipe`

> Légende : **[observé]** = exécuté, la preuve est citée ; **[à vérifier]** = raisonnement ou attente non encore confirmés par une exécution.
> État : **03 ✅ identique à TypeScript** depuis le Sprint 3 (I2 et ADR-7). La forme curryfiée **stockée sans contexte** reste une limite documentée.

## Problèmes étudiés

Source : [`projects/03`](../../projects/03). Même `add` et même sortie qu'à l'exercice 02, mais la transformation passe par `pipe` et par la **forme curryfiée** de `whenIsRight`.

```ts
const newResult = DCommon.pipe(
	result,
	DEither.whenIsRight(
		DArray.coalescing,
	),
);
DCommon.print(newResult);
```

| # | Problème | Détail |
|---|---|---|
| P1 | **Composer des étapes** | `pipe(x, s1, …, sn)` passe la sortie de chaque étape à la suivante, de gauche à droite, de façon synchrone (`pipe.mjs` : une simple boucle). |
| P2 | **Application partielle** | `whenIsRight(coalescing)` (un seul argument) renvoie une **fonction** `(input) => whenIsRight(input, coalescing)`. DuploJS choisit la forme d'après `args.length` **à l'exécution**. En Go, la forme est connue **à la transpilation** (sémantique, §Impacts 8). |
| P3 | **Respect de l'ordre et du conditionnel** | L'étape conditionnelle n'agit que sur un Right, comme dans l'exercice 02. |

Sortie de référence **[observé]** : identique à celle de l'exercice 02 (`Success(3)`, puis `[ 3 ]`). Type de `newResult` : **`Fail | readonly [number]`** **[observé]**.

## Variations considérées

| Variante | Ce qu'elle vérifie | Sortie de référence **[observé]** |
|---|---|---|
| `03-pipe-one-step` | `pipe(3, double)` : une étape, fonction utilisateur, valeur nue | `6` |
| `03-pipe-two-steps` | `pipe(3, double, coalescing)`, puis `pipe(add(1, 2), whenIsRight(double), whenIsRight(coalescing))` : le 2e `whenIsRight` reçoit `6` **nu**, qui n'est pas un Right, et le renvoie inchangé | `[ 6 ]` puis `6` |
| `03-curried-stored` | `const step = whenIsRight(coalescing)`, appelé deux fois : la forme curryfiée doit **exister comme valeur** | `[ 3 ]` puis `[ 7 ]` |

**Constat [observé] :** `pipe(x)` **sans étape** est accepté à l'exécution (fiche de sémantique), mais **refusé par TypeScript** (`Expected 2-16 arguments, but got 1`). Ce cas est hors du TypeScript valide, donc hors périmètre, et la variante prévue `03-pipe-zero` a été remplacée par `03-pipe-one-step`.

## Stratégie

Décisions de l'**ADR-3** (PLAN §0.5) :

| Problème | Traduction Go visée | Responsable |
|---|---|---|
| P1 | **`pipe` inliné en appels séquentiels** : `t0 := x ; t1 := s1(t0) ; …`. L'ordre d'évaluation est conservé, et aucune fonction `Pipe` n'existe à l'exécution. | P3 |
| P2 | **Forme curryfiée = `func` literal** construit d'après le type attendu (signature du résultat de l'appel, donnée par le checker) : `func(input Either[float64]) Either[[]float64] { …whenIsRight inliné… }`. Dans un `pipe`, il est **appelé immédiatement**. | P3 (`createFunctionValue`) |
| P3 | Le corps du `func` literal est exactement le code inliné de l'exercice 02 (forme `Plain`, ADR-2). | P3, P4 |

Go visé (schéma ; conforme au Go produit **[observé]**, voir « Go produit ») :
```go
Generated_t0 := Sourced_result
Generated_t1 := func(input shard_dependencies.Either[float64]) shard_dependencies.Either[[]float64] {
	if input.IsRight() {
		return shard_dependencies.EitherPlainOf[[]float64]([]float64{input.Value})
	}
	return shard_dependencies.EitherRetype[[]float64, float64](input)
}(Generated_t0)
Sourced_newResult = Generated_t1
```

## Justification

- **Un seul mécanisme pour toutes les fonctions data-last** (`whenIsRight`, puis `map`, `matchInformation` et `whenIsRightOtherwise` au Sprint 3) : la forme curryfiée est un `func` literal, la forme directe du code inliné.
- **Coût attendu nul dans un `pipe`** : un `func` literal **appelé immédiatement** et qui ne s'échappe pas est normalement **inliné** par le compilateur Go, sans allocation de closure. **[observé]** au Sprint 3 : `can inline init.0.func1`, puis `inlining call to init.0.func1` (voir « Go produit »). Le repli prévu (inliner le corps directement dans le `pipe`) est inutile.
- **Pas de détection d'arité à l'exécution** : la forme (directe ou curryfiée) est connue à la transpilation. Le test `args.length` de DuploJS n'a pas d'équivalent en Go.

## Go produit

**[observé]** `projects/03/dist/index.ts/index.ts.go`, fonction `init` (extrait) : c'est exactement le schéma visé.

```go
Generated_6 := Sourced_result
Generated_9 := func(Generated_7 shard_dependencies.Either[float64]) (shard_dependencies.Either[[]float64]) {
	var Generated_8 shard_dependencies.Either[[]float64]
	if Generated_7.IsRight() {
		Generated_8 = shard_dependencies.EitherPlainOf[[]float64](([]float64{
			Generated_7.Value,
		}))
	} else {
		Generated_8 = shard_dependencies.EitherRetype[[]float64, float64](Generated_7)
	}
	return Generated_8
}(Generated_6)
Sourced_newResult = Generated_9
```

Les types du `func` literal viennent de la **signature résolue de `pipe`** au rang de l'étape : `(input: Fail | Success<number>) => Fail | readonly [number]` (ADR-7 §2).

**Coût [observé]** (`cd projects/03/dist && go build -gcflags=-m ./...`) :
```
index.ts/index.ts.go:21:17: can inline init.0.func1
index.ts/index.ts.go:31:3: inlining call to init.0.func1
index.ts/index.ts.go:24:72: []float64{...} escapes to heap
```
Le `func` literal est inliné : il n'y a ni appel indirect ni closure sur le tas. Seul le slice s'échappe, parce qu'il finit dans la variable de package `newResult`.

## Limites

- **Forme curryfiée stockée sans contexte** (`03-curried-stored`) **[observé]** : TypeScript type lui-même `const step = whenIsRight(coalescing)` en `(input: unknown) => unknown`, et `step(add(1, 2))` en `unknown` (sonde du checker). Aucun type Go n'est déductible. Le transpileur échoue avec une erreur explicite plutôt que d'inventer un type. Inférer le type à partir des usages sortirait du rôle du checker (ADR-7 §5).
- **`pipe` imbriqué** et `pipe` à plus de 2 étapes avec plusieurs formes curryfiées : non couverts par une variante dédiée.
- **`pipe(x)` sans étape** : hors du TypeScript valide (voir Variations).
