# Exercice 05 : `whenIsRightOtherwise`, fonction fléchée, `map` et `DString.to`

> Légende : **[observé]** = exécuté, la preuve est citée ; **[à vérifier]** = raisonnement ou attente non encore confirmés par une exécution.
> État : **05 ✅ identique à TypeScript** (Sprint 3).

## Problèmes étudiés

Source : [`projects/05`](../../projects/05). `add` est celle de l'exercice 04 (`fail()` si `one === -1`).

```ts
const newResult = DCommon.pipe(
	result,
	DEither.whenIsRightOtherwise(
		DArray.coalescing,
		() => [-12],
	),
	DArray.map(DString.to),
);
DCommon.print(newResult);
```

| # | Problème | Détail |
|---|---|---|
| P1 | **Traiter différemment chaque issue** | `whenIsRightOtherwise(f, g)` : `f(valeur)` si Right, sinon `g(either)`. `g` reçoit l'Either **complet** (`right/whenOtherwise.mjs`). |
| P2 | **Fonction fléchée** | `() => [-12]` : une fonction anonyme, sans paramètre, alors que `g` est appelée avec un argument. |
| P3 | **Fonctions génériques en valeur** | `DArray.coalescing` et `DString.to` sont passées sans être appelées (D15, ADR-7). |
| P4 | **Transformer chaque élément** | `map(to)` : même ordre, même longueur, `to` appelé une fois par élément. Le résultat TS est `readonly (string & Number)[] & LengthEqual<1>`, une **intersection** avec des contraintes DuploJS. |
| P5 | **Format de `DString.to`** | `${value}` en JS, c'est-à-dire `String(n)` : un format **différent** de celui de `print` (`-0` donne `"0"`, ADR-6 amendé). |

## Stratégie

| Problème | Traduction Go | Décision |
|---|---|---|
| P1 | `var r T ; if e.IsRight() { r = coerce(f(e.Value)) } else { r = coerce(g(e)) }`, inliné ; forme curryfiée en `func` literal (même module que `whenIsRight`) | ADR-3, ADR-7 |
| P2 | `func` literal typé par la signature propre de la fonction fléchée ; appelé avec **autant d'arguments qu'il déclare de paramètres** (0 ici) | ADR-7 §3.4 |
| P3 | `coalescing` et `to` **inlinés** d'après le type Go de leur argument (callbacks inlinables) | ADR-7 §3.1 |
| P4 | `out := make([]R, len(arr)) ; for i, v := range arr { out[i] = f(v) }` : taille pré-allouée, ordre conservé. L'intersection ignore les contraintes DuploJS purement typées (`LengthEqual`, `Number`) | PLAN §0.6 |
| P5 | `to` d'un `float64` : `JSNumberToString(x)` (format de `String(n)`) ; d'une `string` : `x` ; d'un `bool` : `"true"` ou `"false"` | ADR-6 amendé |

## Justification

- **Union `[-12] | readonly [number]`** : deux tuples homogènes de `number`, donc le même type Go `[]float64` (ADR-2, règle 1). Les deux branches s'affectent sans conversion.
- **Pas de `Map` générique dans `shard_dependencies`** : `map` est inliné en boucle, donc le callback est appelé directement, sans appel indirect, et `R` est connu à la transpilation.
- **Contraintes DuploJS ignorées** : `LengthEqual<1>` et `Number` sont des marques de type, sans valeur à l'exécution (`map` renvoie un tableau JS ordinaire). Elles sont reconnues **par symbole** dans `@duplojs/lang`, pas par leur nom.

## Limites

- Callback de `map` qui lit son 2e paramètre (`{ index, self }`) : `notSupport` (ADR-7 §5).
- `DString.to` d'un objet (méthode `toString`) ou d'un Either : non modélisé, erreur `duplojs-string-to-unsupported-type`.
- Contrainte d'intersection **non** DuploJS (`A & B` entre deux types utilisateur) : traduite seulement si tous les membres ont le même type Go.
