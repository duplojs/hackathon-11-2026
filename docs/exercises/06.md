# Exercice 06 : `left` avec information, ternaire, `||`, `matchInformation`

> Légende : **[observé]** = exécuté, la preuve est citée ; **[à vérifier]** = raisonnement ou attente non encore confirmés par une exécution.
> État : **06 ✅ identique à TypeScript** (Sprint 3).

## Problèmes étudiés

Source : [`projects/06`](../../projects/06).

```ts
// add.ts
export function add(one: number, two: number) {
	if (one < 0 || two < 0) {
		return DEither.left("negative-operand", one < 0 ? one : two);
	}
	return DEither.success(one + two);
}

// index.ts (après le même pipe qu'en 05)
const message = DEither.matchInformation(result, {
	"negative-operand": () => "un opérande est négatif",
	success: (value) => DString.to(value),
});
```

| # | Problème | Détail |
|---|---|---|
| P1 | **Gauche porteuse d'information et de valeur** | `left("negative-operand", v)` : un `Left<"negative-operand", number>`, dont la valeur **compte** (contrairement à `Fail`). |
| P2 | **Ternaire** | `one < 0 ? one : two` : Go n'a pas d'opérateur ternaire. |
| P3 | **Court-circuit** | `one < 0 \|\| two < 0` : la droite ne doit être évaluée que si nécessaire (D2). |
| P4 | **Aiguillage sur l'information** | `matchInformation` : un handler par information, choisi à l'exécution, et lu dans un objet littéral. |
| P5 | **Types de retour hétérogènes des handlers** | `"un opérande est négatif"` (littéral) et `string` : un seul type Go. |

Sortie de référence **[observé]** (`add(-1, 2)` donne un `Left`, donc la branche « otherwise » s'applique au `pipe`) :
```
[ '-12' ]
un opérande est négatif
```

## Stratégie

| Problème | Traduction Go | Décision |
|---|---|---|
| P1 | `EitherLeftOf[float64]("negative-operand", v)`, V tiré du **type attendu** (le retour inféré `Left<…, number> \| Success<number>` donne `Either[float64]`) | PLAN §0.6 |
| P2 | `var t float64 ; if c { t = one } else { t = two }`, chaque branche gardant ses préparations | ADR-8 |
| P3 | Droite **avec** préparations : `t := a ; if !t { before(b) ; t = b }` ; sans préparation : `\|\|` natif | ADR-8 (D2) |
| P4 | `switch e.Information { case "negative-operand": … case "success": … default: panic(…) }` | ADR-9 |
| P5 | Type de l'appel regroupé par type Go : `string` (ADR-2) | ADR-9 |

## Justification

- **`Left` porteur de valeur et ADR-1** : `Left<"negative-operand", number>` et `Success<number>` ont tous deux la valeur `number`, donc le même `Either[float64]`. Il n'y a aucune conversion aux `return`.
- **Pas de `EitherRetype` ici** : le type d'entrée a une gauche **porteuse de valeur** (`Left`). Re-typer perdrait cette valeur. La coercition ne l'émet donc pas, et ce n'est d'ailleurs pas nécessaire (les deux branches de `whenIsRightOtherwise` produisent `[]float64`).
- **`panic` dans le `default`** : fidèle à l'exécution JS (`TypeError`, aucun garde-fou). TypeScript garantit l'exhaustivité.

## Limites

- `||` et `&&` sur des valeurs **non booléennes** (repli par « truthiness ») : non pris en charge (ADR-8).
- `matchInformation` sur une entrée de forme `Plain`, ou handler avec paramètre sur une variante sans valeur : voir l'ADR-9 §5.
- `left(information)` **sans** valeur : non pris en charge (erreur explicite).
