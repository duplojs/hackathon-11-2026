# Exercice 08 : tuples et déstructuration

> **État : 08 ✅ identique à TypeScript** (Sprint 4).

## Problèmes étudiés

Source : [`projects/08`](../../projects/08). `inputs` est un tableau de tuples
homogènes et le callback de `map` reçoit `[one, two, divisor]`.

| Problème | Détail |
|---|---|
| Tuple homogène | `[number, number, number][]` devient `[][]float64` (ADR-2). |
| Paramètre déstructuré | Un paramètre Go généré porte le slice ; les valeurs utiles sont lues par indice. |
| Nom inutilisé | Un élément jamais référencé n'est pas déclaré, car Go refuse les locales inutilisées. |
| Constante déstructurée | La source est évaluée une fois avant les lectures d'indices. |

Sortie de référence observée :

```text
[ '3', '3', 'échec' ]
```

## Variantes

Voir [`variations/README.md`](../../variations/README.md) :
`08-const-destructure`, `08-unused-binding`, `08-empty-inputs` et
`08-top-level-destructure`. `08-unused-binding` vérifie également qu'un
initialiseur à effet est exécuté lorsque tous ses noms sont ignorés.

## Stratégie

`bindArrayPattern` vérifie que la source Go est une slice, examine les
références par symbole et émet `Sourced_a := source[0]`, etc., pour les seuls
noms lus. Pour un paramètre, les liaisons commencent le corps de la fonction.
Pour `const [a,b] = expr`, `expr` est d'abord lié à un temporaire.

Les éléments omis, rest, valeurs par défaut et motifs imbriqués sont des erreurs
explicites. Un tuple hétérogène reste non pris en charge.

## Go produit

**[observé]** Extrait de `projects/08/dist/index.ts/index.ts.go` :

```go
Sourced_inputs = ([][]float64{
	Generated_4,
	Generated_8,
	Generated_12,
})
Generated_13 := Sourced_inputs
Generated_26 := make([]shard_dependencies.Either[float64], len(Generated_13))
for Generated_24, Generated_25 := range Generated_13 {
	Generated_26[Generated_24] = func(Generated_14 []float64) (shard_dependencies.Either[float64]) {
		Sourced_one := Generated_14[0]
		Sourced_two := Generated_14[1]
		Sourced_divisor := Generated_14[2]
		Generated_15 := Sourced_add.Sourced_add
		Generated_16 := Sourced_one
		Generated_17 := Sourced_two
		Generated_18 := Generated_15(Generated_16, Generated_17)
		var Generated_19 shard_dependencies.Either[float64]
		if Generated_18.IsLeft() {
			Generated_19 = Generated_18
		} else {
			var Generated_23 shard_dependencies.Either[float64]
			{
				Sourced_value := Generated_18.Value
				Generated_20 := Sourced_divide.Sourced_divide
				Generated_21 := Sourced_value
				Generated_22 := Sourced_divisor
				Generated_23 = Generated_20(Generated_21, Generated_22)
			}
			Generated_19 = Generated_23
		}
		return Generated_19
	}(Generated_25)
}
```

Le `func` literal ci-dessus correspond au callback de `DArray.map` ; le
`rightPipe` appelé dans son corps est traduit en `if` imbriqués sans closure.

## Mesures et coût

Le benchmark comparatif et l'analyse `-gcflags=-m` figurent dans
[ADR-11](../decisions/ADR-11-tuples-destructuring.md) et
[`research/tuples/results.txt`](../../research/tuples/results.txt). Dans la
mesure locale, `[3]float64` est plus rapide et évite les allocations des slices
internes, mais `[]T` est conservé pour la cohérence avec la représentation
existante des tableaux homogènes.

Dans `projects/08/dist`, les littéraux `[][]float64` et le résultat préalloué de
`map` s'échappent au tas parce qu'ils sont stockés à portée package. Les helpers
de calcul peuvent être inlinés.

| Contrôle (séquence native équivalente à `check-all`) | Résultat |
|---|---|
| Exercice 08 : transpilation, `go vet`, `go run`, comparaison exacte | ✅ 1/1 |
| Variantes 08 : mêmes contrôles et `tsc --noEmit` | ✅ 4/4 |

## Limites

- Les tuples hétérogènes, omissions, rest, valeurs par défaut et motifs imbriqués
  sont refusés.
- La longueur des slices n'est pas contrôlée à l'exécution ; le contrat est
  celui du type TypeScript.
